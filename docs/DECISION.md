# Model-as-a-Paper v0.1 設計決定

> 本文は実装前の承認済み設計記録です。実装・実行・公開の最新状態は [AUDIT.md](AUDIT.md) とREADMEを参照してください。

決定日：2026-11-06  
状態：初版の構造を固定。科学的品質・GPU速度・復習量の最適性は未測定。  
決定対象：月30米ドル程度で開始する、論文だけからのスクラッチ学習と重み内知識更新。

## 1. 決定

初版は **MAP-44M：12層・隠れ次元512・16,384語彙・GQA 8/2・SwiGLU・共有埋め込みのDecoder-only Transformer** とする。総固有パラメータ数は44,577,280。

H-Net、SSM、深さ方向のループ、MoE、独立した知識Adapter、ES/GRPOは組み込まない。これは一般的な優劣の確定ではなく、この初期予算・再現性・測定目的に対する実装上の決定である。H-Netは次の比較候補として保持する。

知識源は論文と、そこから作成した独立検証済みの学習例。既存一般モデルの重みを初期化に利用しない。推論時の主たる知識源は重みとし、RAGを必須にしない。出力は学習コンテキスト内に収まる短い論文形式から開始する。

## 2. 前版からの変更

1. モデル形状は維持する。
2. 固定500Mトークンで終了するcosineから、warmup→一定学習率→公開候補の時だけcooldownへ変更する。500Mは初回サイクルの上限・観測点であり、完成に必要十分な量ではない。
3. 予算による中断では、重み、optimizer、乱数、sampler/data cursor、累積トークン数を保存し、その位置から再開する。月替わりだけを理由にwarmupをやり直さない。
4. 知識をまだ獲得できていないモデルで忘却を測らない。訂正・保持の評価へ入る前に、旧知識を使えることを確認する。
5. 原文の版を確認できないサンプルを、厳密な時系列の訂正ベンチマークに使わない。
6. 20% Replayは固定的な最適値ではなく、比較のための開始設定とする。

## 3. なぜH-Netを初版にしないのか

H-Netの計算量改善は実証されているが、同品質までのFLOPsと、同品質までのGPU費用は別である。2026年の著者報告は128k語彙を用いた比較系列と改良版アーキテクチャを扱う。本設計の小語彙・共有埋め込みと同じ構成ではない。報告自身が改良版を公開予定と記載するため、旧公開コードへ最新倍率を帰属させない。[S1,S2]

### 同品質でのGPU費用の条件

| 記号 | 意味 | 単位 | 定義 | 定義域・前提 | 型 |
|---|---|---|---|---|---|
| m | 比較モデル | 単位なし | T=Transformer、H=H-Net | 2モデル | 離散ラベル |
| F_m | 同じ事前定義品質までの学習演算量 | FLOP（演算計数） | 当該モデルの累積演算量 | 正、同じ計数規約 | スカラー |
| R_m | 実効演算速度 | FLOP/s | 同規約の演算量を経過時間で割る | 正、同じGPU | スカラー |
| p | 同じ計算リソースの時間単価 | USD/s（SI外） | GPU＋付随CPU/RAM | 正、両モデルで同じ | スカラー |
| K_m | 単純化した実行費用 | USD（SI外） | p F_m/R_m | 構築・保存等の別費用を除く | スカラー |
| G | 同品質までの演算量効率比 | 無次元 | F_T/F_H | 正 | スカラー |
| eta | 実効速度比 | 無次元 | R_H/R_T | 正 | スカラー |

各モデルの実行時間は演算量を実効速度で割った値であり、単価を掛けると費用になる。

```text
K_m = p F_m / R_m
K_H / K_T = (F_H/F_T) (R_T/R_H) = 1/(G eta)
```

したがって同品質でH-Netの実行費用が安くなる条件は `G eta > 1`。追加の環境構築・保存・評価費用があれば別途加算する。FLOP/(FLOP/s)はs、USD/sを掛ければUSDなので単位は整合する。

仮にG=1.28で、eta=0.60なら費用比は約1.302。これは**例示でありMAPでの測定ではない**。1.28という既報値を科学QAの効率倍率として流用しない。

## 4. 小語彙とパラメータ配分

同じ12層・隠れ次元512の本体について、共有語彙行列だけを変えた自己計算：

| 語彙数 | 総固有パラメータ | 語彙行列の比率 |
|---|---:|---:|
| 8,192 | 40,382,976 | 10.39% |
| 16,384 | 44,577,280 | 18.82% |
| 32,768 | 52,965,888 | 31.68% |

少ない語彙が常に安いとは限らない。分割が細かくなり、同じ原文に対する系列長が増えるためである。語彙の最適値はモデル・データ・計算予算と相互依存するという研究結果を踏まえる。[S3]

初版では16,384に固定し、GPUで語彙サイズ探索はしない。これは最適性の証明ではない。Tokenizerはtrain論文のみで作り、数式記号、大小文字、UTF-8を可逆に扱う。Tokenizer実体はモデル学習前に凍結し、以降hashで同一性を確認する。圧縮率の実測はまだ行っていない。

GQA 8/2を8/8のMHAへ戻すと49,295,872パラメータになる。GQAによる差は4,718,592。埋め込み共有とGQAには小型モデルの先行研究があるが、44Mでの科学QA優位は未測定。[S4]

## 5. 固定する構造

| 項目 | 値 |
|---|---|
| 層数・幅 | 12、512 |
| Query/KV head | 8 / 2、head dimension 64 |
| FFN | SwiGLU、内部1,536、biasなし |
| 正規化 | Pre-RMSNorm、eps 0.000001 |
| 位置 | RoPE、base 10,000、64次元全体 |
| 埋め込み | 入力・出力共有、16,384語彙 |
| 階層・SSM・専門家・ループ | 0段・不使用・1・1回 |
| 精度 | FP32重みとAdam状態、BF16 autocast |
| backend | PyTorch SDPA。CUDA GQAの実際のbackendを測定・固定 |
| Context | 1,024から2,048。長文能力をこの長さの外へ外挿しない |
| 有効batch | 非padding予測トークン32,768 |
| 更新 | 全重みSFT、開始LR 0.00002、Replay 20% |
| 初期学習 | AdamW、peak/stable LR 0.0006、betas 0.9/0.95 |

総数の内訳：共有語彙行列8,388,608、Attention7,864,320、FFN28,311,552、norm12,800。合計44,577,280。

GPU用Python/PyTorch/CUDAの組合せは受入試験で固定する。CPU上で確認できたバージョンはPyTorch 2.10.0+cpuであり、これをGPU動作検証の代用にしない。新アーキテクチャのためのカスタムCUDA依存は初版では要求しない。

## 6. 月をまたぐ学習

warmupは最初の10M予測トークン、続いて一定学習率0.0006。公開候補を作ると判断したときだけ、予定50Mトークンで0.00006まで線形cooldownする。cooldownは同じ予算・処理量上限に含める。中断のためにcooldownを強制しない。

この方針はconstant LR＋cooldownの研究と継続事前学習の研究に基づく運用上の選択であり、上記の数値がMAP-44Mに最適と実証されたわけではない。[S5,S6]

公開後に検証済み訂正を受け入れた場合、そのチェックポイントを次の更新の親とする。古い基盤チェックポイントへ戻って訂正を消してはならない。同一目的の中断・再開ではoptimizerを保持し、SFT/訂正など目的が変わる際は明示的に初期化して記録する。

## 7. 訂正を学ぶ教師

学習例には、原主張、仮定、誤った推論箇所または反例、検証済みの修正、元の主張が依然として成立する範囲を含める。誤りを記憶するとは誤文を高確率で出すことではなく、どの条件でなぜ成立しないかを回答できることである。

20% Replayは予測トークン数で定義する。新しい訂正トークン数をそろえると、全トークン数はReplayなしの1.25倍になる。同じ更新step数だけを比較して新知識の接触量を変えない。訂正済みの過去例、未変更の旧知識、回答形式の例を含め、既知の偽命題を無条件の正解として再投入しない。

Replayと出典記録は学習・監査時だけ使用する。回答時に論文DBを参照する設計への変更ではない。少量Replayの価値には先行研究があるが、最適な割合や科学訂正への転移は今回の検証対象。[S7]

データカードによればソースは版別に対応していない。[S8] 初投稿日だけで時間分割せず、訂正前後の資料と近重複を照合する。初期学習に訂正後の本文が混入した事例は、厳密な新知識獲得の試験から除外する。

## 8. 評価ゲートと失敗時の行動

- **実装ゲート**：causal masking、次位置教師、GQA参照実装との一致、重み共有のoptimizer二重登録防止、有限勾配、保存再開、課金制御をテストする。
- **基礎能力ゲート**：旧知識集合の全体正答率と、更新前に正答していた項目の保持率を併記する。前者が低い状態で低忘却を主張しない。
- **更新ゲート**：訂正の直接再現と、未見の言い換え・条件変更・転用問題を分けて評価する。学習データに含めた言い換えを未見と呼ばない。
- **公開ゲート**：独立評価で論理・条件・保留・捏造を確認。初版のscientific publication品質は未達と扱う。

初期pilotは少なくとも30の独立した訂正事例を目指す。複数の質問は同じ訂正にぶら下がるため、独立サンプル数を質問文の数で水増ししない。十分な実事例が集まらなければ一般化の結論はUNCERTAINとする。

確認試験の設計基準案：転移正答率の改善の点推定が10 percentage points以上、95%区間下限が0超、旧問正答率の変化の95%区間下限が-5 points以上。区間は論文/訂正事例単位のpaired bootstrap等で推定する。事前に最大評価時点を固定し、都合のよい途中結果で統計的成功停止をしない。30例だけでこの判定力が足りるとは主張しない。

H: 検証済み訂正＋少量Replayで、旧知識を保ちながら未見問への正確性が向上する。  
T: 同じ親checkpoint・同じ新データ接触量で更新なし、Replayなし更新、20% Replay更新を比較。  
D: 上記の改善・保持条件を満たすときPASS。区間が不十分ならUNCERTAIN。明確に基準不達ならFAIL。  
C: 暗記、旧知識未獲得、修正文への汚染、Replayが新知識を妨げる。  
U: 訂正事例、分野、学習seed、採点者、検証器の誤り。反復測定前に数値的な不確かさを作らない。

## 9. 予算とH-Netへの再検討条件

2026-11-06確認の公式通常Functions料金で、L4 1基・CPU物理2コア・RAM8 GiBは約0.957456 USD/h。GPU課金以外を無視しない。[S9]

本学習枠12ドルは約12.53 resource-hours相当。500M予測トークンをこの枠に入れるには、処理中の平均で約11,082 token/sが必要になる。起動・保存・評価も同じ枠を使えば、学習中はさらに速くなければならない。これは価格と数量からの逆算であり実測速度ではない。

計画枠：データ/Tokenizer2ドル、動作確認/GPU比較2ドル、事前学習12ドル、SFT/評価4ドル、更新/Replay比較4ドル、再実行予備4ドル、合計28ドル。評価・更新へ進む能力が不足した場合は予算を機械的に使い切らず、未達を記録する。Workspaceの実クレジットと上限を確認し、追加の実行時間・トークン数上限を持たせる。[S10]

H-Netの再採用条件は、同じ原文・科学的品質・保持条件において、総GPU費用を意味のある幅（事前目安20%）で下げること。言語モデル損失の改善だけでは足りない。環境構築、失敗した試行、圧縮/復元、評価を費用に含める。

TransformerからH-Netへの変更を単なるtokenizer交換と扱わない。重みの移行費用も再計上する。44M→大規模モデルの拡張も、重み形状を変える場合の再学習・変換費用をゼロと見なさない。

## 10. 確認済みと未確認

確認済み：設定のパラメータ算術、PyTorch meta上の固有重み数、共有行列、予算合計、Replay20%の接触量換算。  
未確認：GPUのforward/backward、科学的品質、収束、語彙圧縮率、H-Netとの差、必要な復習量。  
このセッションではGPUを使わず、クラウド学習を起動せず、公開repoへ書き込んでいない。実コーパスのTokenizer計測は行えていないため、語彙選択を実測最適とは呼ばない。
